# Task: 01 — Project Stage Financial Tracking

Status: pending
Priority: high

## 1. Overview

### ما المشكلة؟
حالياً في النظام، عند تسجيل المصروفات أو إضافة أموال لمشروع ما (سواء عبر نافذة الإضافة السريعة Quick Add أو من داخل صفحة تفاصيل المشروع أو الحسابات المالية)، لا يتم ربط العملية المالية بشكل مباشر وصريح مع المرحلة أو الحالة الجارية للمشروع (مثل مرحلة "الحفر"، "الخرسانة المسلحة"، "البناء"، "التشطيب"). ونتيجة لذلك، لا يمكن لإدارة المشروع معرفة التكلفة الإجمالية التي استهلكتها كل مرحلة على حدة من واقع سجل الحالات.

### ما المطلوب؟
1. إتاحة اختيار وتحديد مرحلة المشروع (والمرحلة الفرعية إن وجدت) عند تسجيل أي مصروف من أي مكان في النظام.
2. التحديد التلقائي للمرحلة النشطة الحالية للمشروع كخيار افتراضي.
3. التحديث التلقائي والديناميكي لتكلفة المرحلة بمجرد إضافة أو تعديل أو حذف أي مصروف.
4. إظهار التكلفة الإجمالية لكل مرحلة بوضوح في "سجل حالات ومراحل المشروع" (Project Phase History Log) وتفاصيل العمليات المكونة لها.

### لماذا نحتاج هذه الـ Feature؟
لتمكين المهندسين ومديري المشاريع من مراقبة تكلفة كل بند ومرحلة هندسية بدقة (مثلاً: معرفة أن مرحلة البناء كلفت 150,000 ج.م ومرحلة الكهرباء كلفت 45,000 ج.م)، ومقارنتها بالميزانية التقديرية.

### ما الأجزاء الحالية في المشروع التي ستتأثر؟
- نافذة الإضافة السريعة (`quick-add.js`)
- وحدة إدارة مراحل المشروع (`project-phases.js` و `phases-catalog.js`)
- وحدة الحسابات المالية للمشروع (`calc.js`)
- صفحة تفاصيل المشروع وسجل المراحل (`project.html` و `project.js` و `project.css`)
- مخزن البيانات المركزي (`store.js`)

## 4. Data Changes

1. **كائن المصروف (`expense` / `transaction`)**:
   - إضافة خاصية `phase_id`: معرف المرحلة (string / null للمصروفات العامة).
   - إضافة خاصية `subphase_id`: معرف المرحلة الفرعية (string / null).
   - إضافة خاصية `phase_name`: نص اسم المرحلة وقت التسجيل للتوثيق السريع.
2. **سجل المراحل (`project.phaseLog[]`)**:
   - دعم حفظ التكلفة اللحظية التراكمية للمرحلة في سجل الحالة:
     `{ id, phaseId, phaseName, status, costAtTransition, totalCost, timestamp, notes }`.
3. **التوافقية مع البيانات القديمة (Backward Compatibility)**:
   - العمليات القديمة التي لا تحتوي على `phase_id` تُعامل كمصروفات عامة للمشروع (`General Expenses`) دون التسبب في أي أخطاء.

## 5. API / Store Functions

- **`calc.phaseCost(project, phaseId)`**: تحسب مجموع كل المصروفات المسجلة لهذا المشروع ولهذا الـ `phaseId`.
- **`calc.phaseBreakdown(project, phaseId)`**: تُرجع تفاصيل المصروفات (الوارد المرتبط إن وجد، الصادر/المدفوع، وقائمة المعاملات المكونة للتكلفة).
- **`calc.allPhasesCosts(project)`**: تُرجع كائناً يحتوي على تكاليف جميع مراحل المشروع دفعة واحدة لتحديث واجهة المستخدم بسرعة.

## 6. UI Changes

1. **في نافذة الإضافة السريعة (Quick Add)**:
   - عند اختيار مشروع، يظهر تلقائياً حقل منسدل "مرحلة المشروع" ممتلئاً بمراحل ذلك المشروع، مع اختيار المرحلة النشطة افتراضياً.
   - إذا تم اختيار مرحلة تحتوي على مراحل فرعية (مثل الخرسانة: حدادة/نجارة)، يظهر حقل اختياري للمرحلة الفرعية.
2. **في بطاقات المراحل (Phase Cards)**:
   - عرض بادج بتكلفة المرحلة: `تكلفة المرحلة: 150,000 ج.م`.
3. **في سجل حالات ومراحل المشروع (Phase History Log)**:
   - إضافة عمود `إجمالي التكلفة` بجانب اسم الحالة وتاريخ اكتمالها، مع زر لعرض تفاصيل المعاملات المالية المكونة لتكلفة تلك الحالة.
